# 图片与文档格式转换插件

日期：2026-10-21。

状态：用户已确认设计，正在实施；各方向完成情况以本轮验证记录为准。

## 已确认需求

- 在 SuperSearch 中新增可选内置格式转换插件，覆盖常见图片和文档转换。
- 文档范围包含 Word、Excel、PPT、PDF、Markdown、TXT、HTML 等常用格式。
- 使用按需安装的本地组件；安装完成后转换在本机执行，不依赖在线转换服务。
- 沿用现有扩展卡片、启用开关、设置保存/取消以及浅色、深色和系统主题。

## 方案与交付边界

采用内置图片转换、按需安装文档引擎的组合。基础图片转换不要求安装大型组件。Office、结构化文本、PDF 内容提取和 OCR 各自只在需要时安装依赖。

已比较三个分发方案：全部随主程序打包会增加所有用户的下载和磁盘负担；在线转换会引入文件上传与服务依赖；按需本地安装符合用户选择。

本次需求包含两个可独立验收的子项目，按以下顺序实施，两批均属于已提出的完整功能范围：

1. 转换入口、任务管理、组件安装，以及图片、Office、Markdown/HTML/TXT 和图片/PDF 转换。
2. PDF 转可编辑文档、表格提取、扫描件 OCR，复用第一批的组件和任务管理。

每批分别编写实施计划并验证。第一批完成时必须明确报告第二批仍未完成，不能将整个格式转换需求标记为已交付。没有通过真实样例验收的方向不显示为可用。

## 转换方向

支持列表按源格式列出具体目标，不将所有扩展名做任意两两组合。以下是产品目标矩阵，实际可用项由组件状态和通过验证的能力共同决定。

| 源文件 | 目标 | 语义与限制 |
| --- | --- | --- |
| JPG/JPEG、PNG、WebP、BMP、TIFF、GIF、ICO | JPG、PNG、WebP、BMP、TIFF、GIF、ICO | 静态图片转换；动画或多页文件必须先明确选择帧/页，不静默只保存第一帧 |
| 图片 | PDF | 一张一页或多张合并，合并前可调整顺序；透明像素在白色页面上合成 |
| PDF | PNG、JPG | 选择页码或全部页，逐页输出；默认 150 DPI，可选 300 DPI，受像素限制约束 |
| DOC、DOCX、ODT、RTF | DOC、DOCX、ODT、RTF、PDF、TXT、HTML | 使用 Writer 对应的输入/输出过滤器，跨格式可能损失样式 |
| XLS、XLSX、ODS | XLS、XLSX、ODS、CSV、PDF | CSV 仅导出用户选中的工作表；提前说明公式结果、样式和多表信息损失 |
| CSV | XLSX、ODS | 选择分隔符与编码，预览后作为数据导入，不执行单元格中的公式 |
| PPT、PPTX、ODP | PPT、PPTX、ODP、PDF | 动画、字体及复杂排版可能变化 |
| Markdown、TXT、HTML | Markdown、TXT、HTML、DOCX、PDF | TXT 以纯文字处理；HTML 仅处理本地文档，移除脚本和远程资源；PDF 经 DOCX 和 Office 引擎生成 |
| DOCX | Markdown | 经结构化文档引擎导出；图片写入同名资源目录并在结果中列出 |
| PDF | TXT、DOCX | 提取文字并重建可编辑段落，明确命名为“提取文字到 Word”，不承诺原版式还原 |
| PDF | XLSX、CSV | 提取检测到的表格；XLSX 每张表一个工作表，CSV 为每张表单独文件；未发现表格时报告无表格，不生成空白成功结果 |
| PDF | PPTX | 每页作为一张完整页面图片放入幻灯片；按钮明确标注“转为图片式 PPT”，不宣称页面元素可编辑 |
| 扫描 PDF、图片 | TXT、DOCX、可搜索 PDF | 按需安装 OCR 与简体中文/英语语言包；文字识别与排版还原分别说明，扫描表格不承诺结构化恢复 |

同格式另存、图片尺寸与 JPG 质量允许作为基础选项。JPG 默认质量 90，透明背景默认白色；图像方向按 EXIF 修正，默认移除位置等隐私元数据。静态 GIF 输出存在调色板量化损失。ICO 输出选择 16/32/48/64/128/256 像素，不通过改后缀伪造图标格式。

HEIC/HEIF、RAW、SVG 光栅化和动画格式互转没有在本轮明确列入目标矩阵，界面不得将其伪装为已支持能力。它们不影响上表常见格式的实施。

## 使用流程

1. 设置 → 扩展中新增“格式转换”，默认关闭。保存后才生效，取消保留原设置。
2. 启用后，文件搜索结果操作菜单增加“格式转换”。使用当前 requestId/resultId 在原生端解析源文件，沿用现有搜索结果边界。
3. 输入独立命令词“转换”或“convert”进入面板；后续用系统文件选择器多选文件。普通文件名如“转换说明.docx”“converter.rs”继续走搜索；输入命令不会启动任务或下载组件。
4. 文件选择器返回原生持有的选择凭据；前端不能通过自造路径授权读取任意文件。首版使用菜单和选择器入口，不另外引入拖放监听。
5. 选择目标、输出目录和必要选项。混合源格式批次只允许共同支持的目标；没有共同目标时提示分别处理。
6. 缺少组件时，显示用途、版本、准确下载大小、预计安装占用、来源和许可。用户点击“安装组件”后才开始下载；安装完成返回原任务草稿，不自动开始转换。
7. 点击“开始转换”创建后台任务。面板显示当前阶段、完成文件数和每项状态；无法测量内部进度的引擎显示不确定进度，不编造百分比。
8. 完成后显示真实输出文件，提供“打开文件”和“打开所在文件夹”。批量中单项失败不丢弃其他成功结果，可仅重试失败项。

输出目录默认原文件所在目录，允许选择统一输出目录；不修改源文件。文件名冲突自动追加“ (转换)”及序号；原生端最终提交时使用禁止覆盖的文件创建/移动语义，防止并发覆盖。多文件输出放入唯一命名的子目录。

## 本地组件

| 组件 | 实现选择 | 安装方式 |
| --- | --- | --- |
| 基础图片与 PDF 页面渲染 | Rust image 编解码；复用现有 Windows PDF 渲染代码的底层能力 | 随主程序；转换使用完整源数据，不使用有损缩略图，也不依赖快速预览开关 |
| Office 文档 | LibreOffice 命令行 | 优先检测标准安装位置与注册表中的受支持版本；缺失时提供固定版本官方安装程序，用户正常完成安装后重新检测 |
| Markdown/HTML/Word 结构转换 | Pandoc | 固定版本官方 Windows ZIP，解压至应用的私有组件目录 |
| PDF 内容提取与文档输出 | 自建独立 Windows helper，封装 pdfplumber、python-docx、openpyxl、python-pptx 与图片/PDF 写入依赖 | 由项目 Windows 构建流程生成独立组件包，包含运行时；用户无需自行安装 Python 或执行 pip |
| OCR | Tesseract 与 chi_sim、eng 语言数据 | 本地验证包提取 Tesseract 项目指向的固定 Windows 发行版，配合固定版本语言数据，不执行其安装器；记录原始来源与校验值。公开再分发前完成各原生依赖所需的完整材料，不宣称由本项目从源码构建 |

PDF helper 负责文字/表格提取和 DOCX/XLSX/PPTX 写入，不承担完整页面编辑器。可搜索 PDF 使用逐页渲染加 OCR 生成，保留页面视觉内容，但不承诺保留原有书签、表单、附件和数字签名。启动前明确显示该影响。

组件目录使用应用本地数据目录下 `components/<id>/<version>/`。任务临时文件在独立 `conversion-jobs/<id>/` 下。复用的系统 LibreOffice 由系统安装器管理；应用中的“卸载组件”仅删除应用私有包，系统安装显示“在 Windows 中管理”，不删除用户原有软件。

下载清单随应用发布，包含组件 id、版本、架构、固定 HTTPS URL、允许的重定向主机、下载字节数、SHA-256、解压后上限、入口和许可证。初版不加载任意远程清单，也不使用运行时“latest”解析。真实包及其校验值未准备好时，该组件不能发布为可安装。

下载使用 `.partial`，校验通过后才解包；拒绝目录穿越、符号链接/重解析点、重复目标路径与解压超限。检查入口及能力探测后，原子切换到可用版本。安装失败保留旧版本；取消清理未完成包。任务使用中的版本不能移除。

组件按 missing/downloading/installing/ready/failed 显示状态，启动时只做本地必要检查，不后台联网或自动更新。插件开关与安装动作分开：安装按钮有明确独立操作，不隐含在设置保存里。

## 任务与生命周期

- Rust 统一管理队列，初版同时运行一个转换任务；最多排队 5 批，每批最多 100 个常规本地文件。
- 单文件上限 200 MiB，单图片解码上限 50 百万像素，单文档最多处理 500 页，单任务输出总量最多 2 GiB。开始前和处理期间持续检查，超限返回可理解的提示。
- 每个外部进程放入应用拥有的 Windows Job Object，后台隐藏启动；普通单文件阶段超时 120 秒，PDF/OCR 阶段最多 10 分钟。内存上限为 1.5 GiB，单页图像逐页处理。
- 固定可执行文件与参数数组，禁止 shell 拼接，不允许用户提交脚本、过滤器或任意命令。LibreOffice 使用独立用户配置，禁止宏与外部链接更新；不连接用户正在使用的 Office 会话。
- HTML/Markdown 和 Office 关系中的外部资源在送入引擎前禁止或移除；只允许明确随源文件授权的本地资源，未授权资源显示缺失提示。离线验收必须包含不存在网络时的正常转换。
- 源文件以原生端验证后打开的文件身份为准，有界复制进任务目录；拒绝设备、网络位置、重解析点和特殊文件，校验格式内容而不只看扩展名。不接受任务提交后被替换的源文件。
- 每项先生成私有临时结果并校验格式与非空内容，成功后才提交输出。失败或取消清理该项临时结果，已成功提交的其他项保留。
- 取消通过原生任务 id 实现，终止应用拥有的进程树，终态不可再次变成成功。关闭面板/隐藏窗口继续任务；重新打开恢复任务状态，不重复提交。
- 关闭插件阻止新任务，已有任务继续，直到完成或用户取消。退出应用前如有任务，提示“取消任务并退出”或“返回”；不因隐藏窗口触发退出提示。异常退出后不自动重跑，只在重启时清理自身遗留临时文件。
- 不持久保存文档正文或转换历史；当前进程内保留最近 20 批结果。英文内部错误经现有本地化边界转为中文反馈，日志不写入正文和完整敏感路径。

## 项目集成边界

前端新增转换面板和独立状态模块，接入现有命令词、扩展设置和键盘路由。App.svelte 只负责入口和视图切换，不继续堆积转换引擎逻辑。Esc 返回上一个视图，任务取消使用独立按钮。

Rust 新增聚合转换模块，将组件安装、任务队列、图片处理和外部引擎调用分开；初版均为静态内置模块，不建设第三方插件运行时或插件市场。IPC 重新检查启用状态、源文件凭据、组件状态、输出目录授权和选项范围。组件下载和转换在阻塞/异步工作任务中执行，不持有搜索缓存或设置锁等待进程退出。

设置新增 `conversionEnabled`，旧存储默认 false。安装组件和运行转换不会修改搜索 Provider、排序、提醒或翻译状态。现有未提交的预览、提醒和翻译改动是当前集成基线，实施时保留。

所有新代码注释使用中文，命令行和内部诊断使用英文，产品界面使用简体中文。

## 验收

1. 命令边界、IME、开关保存/取消、普通文件名与菜单入口；组件安装不会由输入自动触发。
2. 每一个开放的转换方向都有可复现样例，检查目标实际文件头、可被独立读取、中文内容和关键结构；不能只检查子进程退出码。
3. 图片包含透明、EXIF 旋转、大图、损坏文件、多帧/多页提示、GIF 量化和 ICO 尺寸。
4. Office 包含中文字体、多工作表、CSV 编码/公式文本、演示文稿和复杂排版差异。CSV 不得静默只导出第一张表。
5. PDF 包含多页、无表格、表格、文字版、扫描件、中英文 OCR 和图片式 PPT。PDF 转 Word 检查可编辑文字，不以页面截图代替；OCR 与原生文字提取分别记录。
6. 下载包含无网、取消、校验失败、恶意 ZIP、磁盘不足、旧版保留、系统安装器取消和重试；只有真实分发包完整走通后才验收组件安装。
7. 任务包含覆盖冲突、同名源文件、源替换、权限不足、超限、超时、取消竞争、隐藏窗口继续、禁用插件、退出和重启清理。
8. 实际 Windows 环境断网转换验证；浏览器模拟 IPC 只验证交互，不能替代真实引擎和安装验收。检查浅色、深色及工作区受限窗口。
9. 依项目规则执行前端测试/check/build 和桌面 test/check；构建新原生包后运行相应诊断。桌面命令只使用 `scripts/desktop.mjs` 包装，不直接运行 cargo。
10. 新增依赖固定锁文件并更新第三方许可，组件保留自己的许可、版本、源代码来源及分发所需资料。发布前运行依赖审计，不使用历史报告替代本轮验证。

## 依据

- [LibreOffice 转换过滤器](https://help.libreoffice.org/latest/en-US/text/shared/guide/convertfilters.html)：Office 各类导出过滤器及 PDF 导出。
- [LibreOffice 启动参数](https://help.libreoffice.org/latest/en-US/text/shared/guide/start_parameters.html)：Windows soffice.com、无界面转换及独立用户配置。
- [Pandoc 安装](https://pandoc.org/installing.html)：官方 Windows ZIP；PDF 输出另需排版引擎，因此本方案复用 Office 阶段。
- [Rust image](https://docs.rs/image/latest/image/)：常见图片编解码；不把现有预览缩略图当转换源。
- [pdfplumber](https://github.com/jsvine/pdfplumber)：文字与表格提取，扫描件与 OCR 表格存在能力限制。
- [Tesseract](https://github.com/tesseract-ocr/tesseract)：本地 OCR、语言数据与可搜索 PDF 输出。
- [pypdf 文字提取说明](https://pypdf.readthedocs.io/en/stable/user/extract-text.html)：PDF 文字语义、扫描件和资源使用限制。
