# 屏幕扫码扩展设计

日期：2026-10-25

## 已确认的交互

用户希望为 SuperSearch 增加扫描屏幕二维码的可选内置扩展，已选择：

- 默认一键扫描当前屏幕。
- 识别成功先展示内容；网址提供「打开链接」和「复制」两个按钮，不自动打开。

本文将“当前屏幕”定义为触发扫描时鼠标所在的显示器。用户已批准本设计；实施和验证记录见同日的 screen-qr 实现计划。

## 第一版范围

- 在现有「设置 → 扩展」中增加「屏幕扫码」卡片，默认关闭，沿用草稿、保存、取消和折叠说明的模式。
- 搜索框完整输入 `扫码` 或 `qr`（忽略首尾空白，英文忽略大小写）进入扫码面板，回车或点击「扫描当前屏幕」才开始捕获。普通文件名、额外文字、输入法合成和按键重复不触发截图。
- 提供可选的独立全局快捷键，默认未设置；用户配置后可直接扫描。与搜索快捷键冲突或注册失败时给出中文提示，保留此前有效设置。
- 识别一个或多个二维码；单码直接显示，多码按屏幕中从上到下、从左到右排列，并展示仅包含二维码的缩略图与内容摘要。
- 提供「重新扫描」；每次重新确定鼠标所在显示器。
- 第一版不增加框选工具、剪贴板图片读取、摄像头识别、生成二维码或扫码历史。

## 扫描与结果

1. 原生端在触发时确定目标显示器，检查扩展是否启用，并建立本次扫描会话。
2. 隐藏 SuperSearch 自身窗口，确认隐藏操作生效后捕获目标显示器完整画面。这里捕获整个显示器，而非只捕获工作区。
3. 后台任务在内存中解码；完成后释放原始截图，只保留有界的二维码缩略图和解码内容。
4. 本次会话仍有效时恢复窗口并直接展示扫码面板，保持现有窗口位置策略和显示器工作区约束。不要走会清空查询和面板的普通 `show_search` 流程。
5. 没找到二维码时显示「当前屏幕未找到二维码」，提供「重新扫描」；截图或解码失败则显示可理解的中文错误，不把失败误报成空结果。

所有结果先展示为纯文本。对于通过原生 URL 解析的 HTTP/HTTPS 网址，突出域名，提供「打开链接」和「复制」；其他内容提供「复制」。自定义协议、文件路径、脚本和系统命令均作为普通内容展示。复制内容保持解码后的原文，不附加标题、来源或缩略图说明。

打开链接只响应明确的按钮激活。输入框内回车在未扫描时开始扫描，有结果时复制当前选中结果；不通过回车默认打开网址。结果列表支持键盘选择，按钮支持 Tab 聚焦，状态和错误使用可访问提示。复制成功显示「已复制到剪贴板」；复制或打开失败保留结果，允许重试。

Esc 退出面板并清除会话结果。扫描期间用户重新呼出搜索、打开设置、隐藏窗口、关闭扩展或退出应用，均使旧会话失效；迟到结果不能抢占新视图、重新弹窗或恢复旧内容。重复触发不并发排队；一次扫描结束或失效后才接受下一次捕获。

## 模块与接入位置

- `src/qr-scan.ts`：精确命令识别、前端会话状态、过期结果抑制和中文错误映射。
- `src/QrScanPanel.svelte`：未启用、待扫描、扫描中、空结果、单码、多码和错误状态，沿用现有中性色与主题变量。
- `src-tauri/src/qr_scan.rs`：有界捕获及解码流程、会话结果、会话动作校验和生命周期失效。
- Windows 捕获实现封装在原生模块内，复用现有 Windows 平台依赖和坐标体系。物理像素坐标与显示器矩形统一计算，支持负坐标及混合 DPI。
- 解码实现优先验证 ZXing-C++ 的 Rust 绑定，官方提供多码读取及码位置信息。集成前使用合成二维码夹具确认 Windows 构建、中文解码、多码及缩略图提取，并检查新依赖许可和包体积。
- `src/App.svelte`、`src/bridge.ts`、`src/types.ts` 和原生设置模型仅承担接入。新增设置兼容旧配置，不另建插件运行时。
- `src-tauri/src/main.rs` 和设置提交逻辑按快捷键实际身份分别路由搜索与扫码，保留现有搜索快捷键注册、回滚和错误报告行为。

捕获、解码和恢复窗口期间不持有搜索缓存或设置锁。截图留在原生端，前端只接收二维码缩略图及文本；不向 WebView 发送完整屏幕图像。扫码使用独立结果标识，不能将二维码内容当作本地搜索结果凭据。

## 边界与资源

- 扩展开关在每次扫描、复制和打开操作时由原生端重新检查。
- 打开和复制仅提交当前会话及结果 ID，由原生端解析对应内容；不接受前端任意 URL 或任意文本来执行扫码动作。
- 每次最多保留 32 个结果，每条文本最多 16 KiB，每张缩略图最长边 160 像素；达到数量或内容上限时明确提示，不能静默截断后复制或打开错误内容。
- 截图上限为 40 百万像素，像素缓冲上限 160 MiB，尺寸乘法检查溢出。超过上限给出中文说明；不能以缩小整屏图像代替原图后承诺小二维码识别率。
- 不持续监听屏幕，不联网解码，不保存截图或扫码内容，不将它们写入日志、诊断或使用历史。会话关闭或替换时清理结果及缩略图。
- 受系统保护的桌面或捕获受限的窗口可能无法读取，不承诺所有屏幕内容均可识别。

## 验证与验收

- 原生合成图片夹具：单码、多码、重复内容处于不同位置、中文、纯文本、旋转码、反色码、空图、损坏图片、数量/文本/像素上限及溢出。
- 原生动作与生命周期：默认关闭、旧设置兼容、保存取消、快捷键冲突和回滚、禁用后拒绝操作、过期 ID、HTTP/HTTPS 与其他协议、重复触发、取消与迟到回复。
- 前端：精确命令边界、输入法与重复回车、扫描中禁用重复操作、单码/多码/空结果/错误、选择与复制、显式打开、退出后的迟到结果、中文与长网址布局。
- 运行项目规定的前端测试和类型检查，以及通过 `npm run desktop:*` 包装器运行的 Rust 测试与编译检查；依赖变动补充审计及许可记录。
- 使用生产前端的明确合成响应检查浅色、深色、窄窗口和键盘交互；浏览器预览不进行真实截图、剪贴板写入或浏览器打开。
- Windows 实测目标屏幕选择、自身窗口隐藏、扫描结果恢复、100%/125%/150%/200% 缩放、双屏负坐标、混合 DPI 和扫描中切回搜索。未实际执行的物理屏幕场景必须标明未验证。
- 按 `docs/design/qa.md` 检查界面，记录新的验证证据，不用历史报告替代。
